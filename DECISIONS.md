# cennge-ui — решения

Зафиксировано 2026-10-18 по итогам интервью и анализа конкурентов.

## Позиционирование
Эстетика уровня Modrinth/Linear, обновления как у Mantine: обычный npm-пакет, `npm update` — и баг
исправлен во всех проектах. Доказательство качества — e2e-матрица оверлеев.

## Пакет
- `cennge-ui`, без scope, MIT. Один вход + `cennge-ui/styles.css`.
- `"type": "module"`, `"sideEffects": ["*.css"]`, `exports` с types/import/require. Сборка tsup (ESM + CJS + .d.ts),
  `"use client"` в выходных файлах.
- ESM собирается с разбиением: по чанку на компонент, index.js только реэкспортирует. Одним файлом tree shaking
  не работал: импорт одного Button тянул 87% библиотеки (57 KB gzip), теперь ~2 KB. `pnpm size` в CI держит
  пределы для типичных импортов. CJS — один файл: require() всё равно не вытряхивается.
- peer: `react`, `react-dom` — 18 и 19 в приоритете, 17 поддерживается. `tailwindcss` v4 — peer.
- deps: `radix-ui` (единый пакет), `tailwind-variants`, `tailwind-merge`, `clsx`. Никакого framer-motion.
- Типы Radix не выходят в публичный API — фундамент можно заменить (Base UI) без breaking changes.
- Ради React 17: без прямых `useId`, `useTransition`, `useSyncExternalStore` и API React 19; `forwardRef`.

## Подключение у пользователя
```css
@import "tailwindcss";
@import "cennge-ui/styles.css";
@source "../node_modules/cennge-ui";
```

## Визуальный стиль (ориентир — Modrinth, без заимствования кода: у них GPL-3.0)
- **Тёмная тема первой**, светлая полноценная. Переключение — class `dark` на `<html>` (совместимо с next-themes).
- **Глубина слоями поверхности**: `--cennge-surface-1…4` (фон → карточка → поднятый элемент → кнопка),
  тени вторичны.
- **Тактильность**: внутренний блик снизу у solid, слоистые тени, нажатие `scale(0.97)`,
  свечение в цвет акцента у варианта `shadow`.
- **Фирменный акцент — оранжевый** (`primary`). Полностью заменяем: пользователь переопределяет
  `--cennge-primary-*` (или включает пресет — см. ниже) и получает синий/зелёный/любой.
- Три уровня каждого цвета: насыщенный, `-highlight` (~25%), `-bg` (~10%) — основа flat/faded.
- Крупные радиусы, средняя плотность: radius md ≈ 12px, карточки 16px, кнопка md = 40px. Шрифт Inter (опционально,
  через переменную `--cennge-font-sans`).
- Анимации: свои keyframes, только transform/opacity, `prefers-reduced-motion`.

## Темизация (CSS-first, модель HeroUI)
- Префикс переменных `--cennge-*`, маппинг в Tailwind через `@theme` → `bg-primary`, `text-primary-foreground`…
- Цвета: `default, primary, secondary, success, warning, danger, info`. Каждый: шкала 50–900, `DEFAULT`, `foreground`.
- Layout-токены: радиусы sm/md/lg, толщина границ, disabled-opacity.
- Пресеты акцента в styles.css: `data-accent="blue|green|purple|…"` — переопределяют только `primary`.
- Генератор шкалы из одного цвета — позже (CLI или страница docs).

## API компонентов
- `color` (7), `variant` (7, как HeroUI: solid, bordered, light, flat, faded, shadow, ghost),
  `size` (sm/md/lg), `radius` (none/sm/md/lg/full), `isDisabled`, `isLoading` (+ нативный `disabled`).
- Переопределение: `className` + `classNames={{ slot }}` (slots из tailwind-variants, слияние tailwind-merge).
- Dialog, Dropdown, Card — составные части (`DialogContent`, `DialogHeader`…) + `classNames`.
- `asChild` вместо полиморфного `as` (лёгкие типы).
- Формы: controlled и uncontrolled везде; у Select будет очистка значения.
- `CenngeProvider` — необязательный: дефолтные size/radius/color, `reducedMotion`, Radix TooltipProvider. Тема — не через Provider.
- Старт: Button, Input, Card, Dialog, Dropdown, Badge, Tooltip. Следующий — Combobox/MultiSelect.

## Инфраструктура
- git + GitHub + Actions, pnpm.
- Тесты: Vitest + Testing Library; Playwright (оверлеи, axe, скриншоты 7×7 комбинаций в light/dark).
- CI: typecheck, lint, тесты, publint, arethetypeswrong, матрица React 17/18/19. Публикация changesets с provenance.
- `playground/` на Vite — песочница и стенд для Playwright.
- Next.js App Router в CI (`tests/next`, `pnpm check:next`): приложение ставит пакет из `pnpm pack` и собирается вне
  репозитория, так что видит только объявленные зависимости. Страница рендерит весь playground на сервере;
  браузеры гидратируют её из часового пояса, где уже другой день, и с третьей локалью, в production и в dev.

## Даты, таблицы и клавиатура (2026-10-19)
- Даты и время — ISO-строки без часового пояса: `"2026-10-19"`, `"14:30"`, как у `<input type="date">`. Переживают
  JSON, FormData и server actions; арифметика в UTC, переход на летнее время не сдвигает день.
- Названия месяцев и дней, первый день недели и порядок полей при вводе — из `Intl` по `locale` провайдера.
- «Сегодня» знает только браузер: сервер рендерит в своём часовом поясе, статическая страница — в день сборки.
  На сервере и при гидратации календарь не отмечает сегодня, а без значения держит место невидимым месяцем;
  после гидратации — месяц и сегодня пользователя. `useIsHydrated`: useSyncExternalStore, на React 17 — layout-эффект.
  Без date-fns и react-day-picker: у shadcn обновление react-day-picker ломало календарь (#4366).
- Год и месяц выбираются сеткой внутри календаря: того же размера, со своей прокруткой и клавиатурой.
  Нативный `<select>` на компьютере раскрывал полтораста лет на всю высоту экрана. Ввод с клавиатуры терпимый:
  `19.10.2026`, `19/10/26`, `19102026`, ISO. Текст, который не дата, остаётся в поле с причиной под ним.
- Где Radix не покрывает виджет (календарь, дерево, ⌘K), клавиатура пишется по паттернам WAI-ARIA APG и
  проверяется e2e во всех движках. Нестабильные примитивы Radix (OTP, поле пароля) спрятаны за нашим API.
- Таблица — нативная разметка, сортировка через `aria-sort`. TanStack Table подключается без адаптеров:
  `TableColumn` принимает `getIsSorted()` и `getToggleSortingHandler()` как есть.
- Диалоги, открытые кодом (из меню, по сочетанию клавиш), возвращают фокус туда, где он был до открытия.
- Фокус с клавиатуры виден у всего, до чего доходит Tab (WCAG 2.4.7): e2e сравнивает, как элемент нарисован с фокусом
  и без, во всех фикстурах и во всём playground. axe этого не видит. В Tailwind v4 `outline-none` обнуляет
  `--tw-outline-style`, поэтому рядом с `focus-visible:outline-2` всегда стоит `focus-visible:outline-solid`.

## Текст из Markdown (2026-10-19)
- `Prose` — единственный компонент, чьи стили лежат в `styles.css`, а не в tv(): десятки правил для h1–h6, списков,
  кода и таблиц читаются как CSS, а класс `cennge-prose` работает и без React (серверный HTML, MDX).
- Правила в слое `components` и в `:where()`: любая утилита на элементе внутри побеждает, `not-prose` выключает стили.
  Отступы в em — размер меняет только font-size. Широкие блоки кода прокручиваются и получают tabindex.

## Карусель (2026-10-19)
- На нативном scroll-snap, без Embla: свайп, трекпад, колёсико и стрелки работают как у любой прокрутки, мышь
  перетаскивает поверх. Сколько слайдов видно — CSS-переменная `--carousel-per-view`, поэтому адаптивность классами.
- По умолчанию стрелки под слайдами (`CarouselControls`): поверх текстовых карточек они закрывали текст.
  Поверх слайдов — по флагу `arrows`, для галерей картинок.
- Автопрокрутка по WAI-ARIA APG: пауза под мышью, остановка при входе фокуса, кнопка паузы есть всегда
  (WCAG 2.2.2), при reduced motion сама не стартует; пока крутится, aria-live выключен.

## Формы (2026-10-19)
- `<Form validationErrors>` раздаёт ошибки полям по `name`: из server action, из API. Поле показывает свою
  ошибку, если она задана, иначе ошибку формы. Ошибка сервера уходит, как только поле правят.
- Проверки браузера (`required`, `type`, `minLength`, `pattern`) остаются браузерными, но показываются под полем:
  форма отменяет событие `invalid` и фокусирует первое неверное поле. Отдельной схемы валидации нет:
  zod/valibot остаются на сервере и возвращают ошибки по именам.
- Форма обновляет своё состояние после события ввода, а не во время: рендер посреди события возвращал
  контролируемому полю старое значение, и символ терялся.
- Сброс формы не стирает ошибки сервера: React 19 сбрасывает форму сразу после action, как раз когда они приходят.

## Навигация (2026-10-19)
- NavigationMenu оставляет общую панель Radix (переключение без мигания), но ставит её под открытый пункт и
  удерживает в окне — главная жалоба на Radix (#1462). Открытие по клику — штатный приём Radix с preventDefault.
- Виртуализация своя, без зависимости: суммы высот, двоичный поиск видимого, замер строк ResizeObserver и
  компенсация прокрутки, когда меняется строка выше видимой области. Каждая строка несёт aria-setsize/aria-posinset.
- Combobox виртуализируется сам после 100 вариантов; активный вариант всегда в DOM ради aria-activedescendant.

## Карта (2026-10-20)
- Отдельный вход `cennge-ui/map`; `maplibre-gl` 6 — необязательный peer, загружается динамически, когда карта
  монтируется. Вход в общей ESM-сборке с чанками: провайдер и утилиты одни на всю библиотеку. Только ESM, как
  и maplibre-gl 6; attw проверяет его профилем esm-only.
- Подложка по умолчанию — OpenFreeMap: без ключа и лимитов, коммерческое использование разрешено. У CARTO
  нужен ключ, бесплатно для коммерции до 1M тайлов в месяц.
- Своя подложка: серый Positron перекрашивается токенами темы при загрузке (transformStyle). Слой
  распознаётся по id: суша — поверхности, вода — с долей info, парки — с долей success, подписи — foreground
  и muted. Одна раскладка в обеих темах; смена темы перезагружает стиль, смена акцента — нет.
- Данные: хороплет — ступени шкалы цвета (светлая тема 100→400→700, тёмная 800→500→300), легенда берёт те же.
  Кластеры считает MapLibre, но рисуем их своими маркерами: группы и точки — кнопки, в DOM только видимое.
- Линии (маршрут, дуги) и данные — один хук: источник и слои добавляются с каждым стилем под подписями карты.
- Маркеры, подсказки и popup — свой React-слой поверх canvas, не Marker/Popup MapLibre: наши стили, фокус и
  клавиатура. Позиция пишется в transform на событии move, без рендеров React. Popup — немодальный диалог,
  растёт от стрелки и сдвигает карту, чтобы поместиться целиком.
- CSS MapLibre не нужен: несколько его правил (canvas, boxzoom) — классами на контейнере. Атрибуцию рисуем
  сами: HTML источников разбирается до текста и http(s)-ссылок.
- Воркер MapLibre 6 подключает приложение (сборщики его не находят). `setMapWorkerUrl` запоминает адрес и не
  импортирует maplibre-gl, иначе пропала бы ленивая загрузка. Для Next.js — файлы воркера в public/.
- Тесты: тайлы OpenFreeMap подменяются офлайн-стилем в общей фикстуре; Firefox headless — с webgl.force-enabled.

## Курсор, диалоги, тема (2026-10-31)
- У всех включённых элементов управления — курсор-указатель (жалоба №1 на кнопки shadcn/ui); тест обходит
  playground целиком. У загружающейся кнопки — cursor-wait: ей оставлены pointer events, hover и нажатие
  выключены. Отключённая ссылка через asChild не переходит ни по клику, ни по Enter.
- Контент модального диалога — внутри оверлея, не рядом (схема Radix для прокручиваемых оверлеев): иначе
  блокировка прокрутки Radix гасит прокрутку в попапах из портала, открытых из диалога (Radix #1159; #3423
  спасает только слои самого Radix). Фон рисует ::before оверлея: внутри элемента с backdrop-filter WebKit на
  Linux перестаёт отрисовывать страницу.
- Тема: ThemeScript в <head> ставит класс до первой отрисовки и следит за системой и вкладками; useTheme до
  гидратации отдаёт undefined (useSyncExternalStore, на React 17 — state после монтирования), поэтому первый
  рендер совпадает с HTML сервера. На <html> нужен suppressHydrationWarning — только для его атрибутов.

## Графики (2026-10-31)
- Свои, на SVG, без библиотеки графиков: Recharts — тяжёлая зависимость, и её обновления у shadcn ломаются.
  Отдельный вход `cennge-ui/charts`, только ESM, в общей сборке с чанками (один провайдер).
- Оси — HTML, сетка — SVG, всё в процентах: сервер присылает их на своих местах. Столбцы и линии рисуются в
  пикселях после замера, viewBox с preserveAspectRatio="none": между resize и новым замером они тянутся
  вместе с осями. Кольцо и спарклайн — в фиксированном viewBox, целиком на сервере.
- Палитра из восьми оттенков проверена скриптом, не на глаз: полоса светлоты и хрома, 3:1 на всех
  поверхностях, соседние слоты различимы при протанопии и дейтеранопии (ΔE ≥ 8.5) в обеих темах. Первый слот —
  акцент, порядок остальных подобран для каждого пресета. Девятая серия — серая, новых цветов не бывает.
- Метки по правилам dataviz: столбец не толще 24px, скруглён на конце данных; линия 2px, точки 8px с кольцом;
  заливка области — размывка цвета; сетка — волосяные линии. Подсказка — значения всех серий в точке; с
  клавиатуры — стрелки и live region; для скринридеров — таблица.

## Цели и трекеры (2026-11-15)
- Библиотеку будут использовать для трекеров (фитнес, еда, привычки). По исследованию приложений и отзывов
  первым этапом добавлены ProgressRing, RangeMeter, StatTile и цели на графиках (`references`, точки, `movingAverage`).
- ProgressRing — отдельный компонент, не режим CircularProgress: тот показывает ход задачи (`progressbar`, стоп на
  100%), этот — цель человека (`meter`, перевыполнение — второй круг с тенью на конце). Каждое кольцо — скрытый
  `meter` с `aria-valuetext`; `aria-valuenow` не выходит за `max`, перебор говорит текст. Середина — для глаз,
  скрыта от скринридеров. Имя кольца — `aria-label`, как у графиков: видимой подписи у кольца нет.
- RangeMeter повторяет смысл `<meter>`: `low` — пол, `high` — потолок. Статус пишется словами; «не дошли» — серый,
  не акцент (зелёный или красный акцент читался бы как «в норме» или «ошибка»), «в норме» — success, «перебор» —
  warning и штриховка. Без цели и без `max` полосы нет: она всегда была бы заполнена на 80%.
- StatTile: цвет изменения задаёт `goodDirection` (вес вниз — хорошо), скринридер слышит «better» или «worse».
  Изменение, которое при округлении равно 0, — нейтральное.
- Все слова для скринридеров переводятся через `labels`, числа — по локали провайдера.
- Перед коммитом — ревью с четырёх сторон (доступность, API, дизайн, краевые случаи) и проверка каждой находки.

## Мобильная оболочка (2026-11-16)
- Второй этап для трекеров: BottomNavigation, BottomBar, FloatingActionButton, SwipeActions и нижний лист с высотами в
  Drawer (не отдельный компонент: тот же Dialog, тот же фокус и Escape).
- Всё, что закреплено снизу, складывается само: высоты пишутся в `--cennge-bottom-nav` и `--cennge-bottom-bar` на
  `<html>` (последний смонтированный из нескольких), панель стоит на навигации, FAB и нижние тосты — над ними, отступ
  под индикатор дома учитывается один раз.
- Жест никогда не единственный путь: у SwipeActions всегда есть меню с теми же действиями, у листа ручка — кнопка
  (клик и стрелки). Свайп — только пальцем и пером; мышь пользуется меню, выделение текста не ломается.
- Лист при перетаскивании меняет стиль напрямую, без рендера на каждый кадр; в покое он высотой своей точки, чтобы
  всё содержимое прокручивалось в видимую область. Палец, остановившийся перед отпусканием, — не бросок.
- `inert` ставится свойством на элементе: React 17 и 18 не передают его как проп.
- Перед коммитом — два независимых ревью (доступность и баги; дизайн и API), 30 находок, исправлены все подтверждённые.

## Сайт документации (2026-11-08)
- `site/` в том же репозитории, пакет workspace: страницы собираются на `dist/` текущего коммита, поэтому
  примеры и таблицы пропсов не расходятся с кодом. Next.js App Router со статическим экспортом: размещается на
  любом статическом хостинге. Язык — английский.
- Сайт сделан на самой библиотеке: боковая колонка — Sidebar, поиск — CommandDialog, тема и акцент — ThemeSwitch
  и ToggleGroup. Ошибка библиотеки видна на её собственной документации.
- Страница компонента устроена как статья определителя: живой компонент на «табличке» с пронумерованными
  заметками, рядом «приметы» (импорт, размер, паттерн WAI-ARIA, клавиши, SSR, тесты, исходники), ниже —
  когда применять, похожие компоненты, примеры, пропсы.
- Приметы и пропсы не пишутся руками: размер считает esbuild по `dist/` (как `pnpm size`), тесты — по e2e-спекам,
  которые открывают фикстуру с компонентом, пропсы — TypeScript compiler API по экспортированным `...Props`.
- Код примеров — это файл примера целиком, подсветка Shiki при сборке, цвета токенов из переменных темы:
  код перекрашивается вместе с акцентом.
- Каждое утверждение на странице проверено по исходникам, тестам, README или этому файлу; данные в
  примерах — репозитории владельца, карты — Нью-Йорк.
- e2e сайта: каждая страница в пяти браузерных проектах, axe WCAG 2.2 AA в тёмной и светлой теме, чистая
  консоль, без горизонтальной прокрутки, все внутренние ссылки живые.

## Известные риски
- 49 комбинаций color×variant на компонент → только с визуальными тестами.
- React 17 сужает набор API.

  берёт функцию, которая выбрасывает обновление. Тесты тостов на 17 помечены `it.fails` и покраснеют, когда Radix починит (radix-ui/primitives#4228).

  на него и сразу уходит в панель. axe считает это нарушением aria-hidden-focus; в тестах этот span исключён.
