## When to use

Use a DatePicker for a date in a form: a release, a due date, a birthday. Some people type dates and others click them, and it takes both. The value is an ISO string with no time zone, `"2026-11-19"`, the same as `<input type="date">` gives, so it goes to a server unchanged.

Typed text is read when the field loses focus or on <kbd>Enter</kbd>, in the order the locale writes dates and with any separators. Text that is not a date, or a date it cannot take, stays in the field with the reason under it.

## Similar

- [Calendar](/docs/calendar/) is the same month grid, always open on the page.
- [DateRangePicker](/docs/date-range-picker/) takes a start and an end in one calendar.
- [TimeInput](/docs/time-input/) takes the time of day; put the two side by side for a date and a time.

## Type it or pick it

The calendar button opens the calendar on the chosen day, or on today. Picking a day closes it and returns focus to the button. An emptied field sets the value to `null`.

## Order and separators from the locale

The placeholder, the way the field writes the date and the order in which it reads typed numbers come from `Intl` for the `locale`: month first in the United States, day first in Britain, year first in Japan. Set it once on [CenngeProvider](/docs/provider/), or per field. These three share one value: type in any of them.

## Limits counted from today

`minValue` and `maxValue` disable the days outside them in the calendar and turn a typed date outside them down with the reason. `isDateUnavailable` crosses single days out of the calendar and turns them down when typed. Only the browser knows the reader's today, so read it after mount; until then `null` means no limit.

## In a form

With a `name`, a hidden input carries the ISO date. <kbd>Enter</kbd> in the field reads the typed date before the form is submitted, so typing and pressing <kbd>Enter</kbd> sends it. Inside a [Form](/docs/form/), `isRequired` and errors from your server show under the field.

## In another language

`formatError` turns each refusal into your text: it receives `invalid` with the locale's pattern, `outOfRange` with the limits, or `unavailable` with the date. `labels` names the calendar button and the calendar's controls, and `placeholder` replaces the pattern shown in the empty field.

</Example>

## Accessibility

The field is a text input with its label, so screen readers announce it as one, and a refusal sets `aria-invalid` with the reason as its description. The calendar button is named "Choose date", and so is the dialog it opens. The calendar moves focus to the chosen day when it opens. The first <kbd>Escape</kbd> closes an open month or year grid, the next one the calendar.
