## When to use

Wrap Prose around content you did not write as JSX: Markdown turned into HTML, an MDX page, a post from a CMS, a README. It styles the elements that renderers produce, headings, paragraphs, lists, task lists, code, tables, quotes, details and images, in the theme's colours and with the accent on links.

For text you lay out yourself in JSX, use Tailwind classes directly; Prose adds nothing there.

## Similar

- [Snippet](/docs/snippet/) is a single command with a copy button. Prose styles whole code blocks as part of the text, without a button.
- [Kbd](/docs/kbd/) draws a key cap with symbols. A bare `<kbd>` inside Prose gets a plain box.

## HTML from a CMS or a renderer

Prose is a `<div>`, so it takes `dangerouslySetInnerHTML` as well as children. A table keeps Markdown's column alignment and wraps long cells instead of pushing the page sideways. Only render HTML you trust or have sanitised.

## Sizes and your own element

`size` is `sm`, `md` or `lg`: 14, 16 or 18 pixels. Margins and paddings are in `em`, so the whole block scales with it. With `asChild`, Prose styles your element, here an `<article>` and an `<aside>`, instead of adding a `<div>`.

</Example>

## Components and classes inside

The styles sit in Tailwind's `components` layer, below the utilities, so a utility class on an element inside wins over them, as `text-sm text-muted` does on the last line here. `not-prose` switches them off for a whole subtree, so a component keeps its own look.

</Example>

## Without React

The styles are a class in `cennge-ui/styles.css`, so server-rendered HTML can use them without the component. Add `cennge-prose-sm` or `cennge-prose-lg` for the other sizes.

```html
<article class="cennge-prose">
  <h1>Release notes</h1>
  <p>…</p>
</article>
```

The component adds one thing the class cannot: a code block that scrolls sideways becomes keyboard-focusable, and stops being a tab stop when it fits again.
