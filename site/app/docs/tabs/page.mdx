## When to use

Tabs hold a few panels about one thing, a package's readme, versions and dependencies say, and show one at a time without leaving the page. Every `TabsTrigger` needs a `TabsContent` with the same `value`: screen readers go from the tab to the panel it controls.

## Similar

- [ToggleGroup](/docs/toggle-group/) switches a filter or a view with no panels behind it; when nothing would go in a `TabsContent`, use it instead.
- [Accordion](/docs/accordion/) opens sections in place, several at once if you like, all readable in one scroll; Tabs show one panel and hide the rest.
- [Sidebar](/docs/sidebar/) and [NavigationMenu](/docs/navigation-menu/) take the reader to another page; Tabs change what this page shows and leave the address alone.

## Variants and colours

`solid` sets the tabs on a sunken track and raises the selected one, `underlined` draws a line under the list and a bolder one under the selected tab, `light` tints the selected tab and nothing else. `color` paints the selected tab; `primary` follows the accent.

## Full width

`fullWidth` stretches the list across its container and gives every tab an equal share. Only the open panel's content is rendered, so a field in a panel you leave starts empty when you come back; keep its value in state above the Tabs if it should last.

</Example>

## Accessibility

Name the list with `aria-label` on `TabsList`. Only the selected tab is in the tab order: the arrows move between tabs, skipping those with `isDisabled`, and Tab goes on into the open panel, which takes focus itself so its content is reachable even when it holds nothing focusable.
