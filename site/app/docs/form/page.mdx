## When to use

Wrap fields in a Form when some of their errors come from elsewhere: a server action, an API, a check only the server can make, such as whether a name is taken. Return the errors as an object keyed by field name and pass it as `validationErrors`. Each one shows under its field and goes away as soon as that field is edited.

Form adds no validation of its own. `isRequired`, `type="email"`, `minLength` and `pattern` stay the browser's checks, shown under the field rather than in a tooltip; a schema library such as zod stays on the server and sends its errors back by name.

## Similar

- A plain `<form>` takes the same fields. The browser then shows its checks as tooltips, and a server error reaches a field only through that field's own `isInvalid` and `errorMessage`.
- [Forms](/docs/forms/) is the guide to fields in forms: controlled or not, and with react-hook-form. This page is about the component.

## Errors from your server

Pass the errors the server returned, keyed by `name`. Each new object shows its whole set and moves focus to the first field with an error, in the order of the form. Several messages for one field, as an array, show together. Send it as it is: dev@example.com is a collaborator already. Then try another address.

## With a React 19 action

With `useActionState` the errors are part of the action's state. React empties the form after every action, so give the field the submitted value back as `defaultValue`, with a `key` that makes it take it. Server errors survive that reset: they arrive at the same moment.

## The browser's checks

Publish it empty. The form cancels the browser's `invalid` events, so each message appears under its field, in the browser's own words and language, and focus goes to the first field to fix. While you type, the message follows the field and goes once the value passes.

## Your own field

`useFormField(name)` hands a field of yours the form's error for that name, and its `markEdited` drops the error once the value changes. Set `data-field-name` on the field's wrapper, so the form can find the field and focus it.

## Accessibility

A field with an error gets `aria-invalid`, and the message is tied to it with `aria-describedby`, so screen readers read the two together. Focus goes to the first field with an error both when the browser blocks a submit and when a new set of errors arrives.
