## When to use

Use radios when there are a few options, only one can be chosen, and people decide better with all of them in view: a visibility, a version bump, a plan. Each option can carry a line of description that stays in view, where a Select shows it only while its list is open.

## Similar

- [Select](/docs/select/) keeps the options in a list until it is opened; better when there are many of them or space is short.
- [ToggleGroup](/docs/toggle-group/) is a row of buttons for switching a view; it has no `name` and sends nothing with a form.
- [Checkbox](/docs/checkbox/) allows any number of choices at once.

## Descriptions and a disabled option

`description` sits under a radio's label, inside the same `<label>`, so a click on it chooses the radio too. A disabled radio stays visible and the arrow keys skip it.

## Horizontal

`orientation="horizontal"` lays the radios out in a row that wraps when it runs out of room, and the left and right arrows move between them.

## Required, in a form

With a `name`, the chosen value goes into the form's data. Inside a [Form](/docs/form/), `isRequired` stops a submit with nothing chosen: the label and the circles turn red, the browser's message shows under the group, and focus moves to the first radio.

## Accessibility

The group is a `radiogroup` named by its `label`, with the description or error linked by `aria-describedby` and `aria-invalid` while it has an error. Each radio is named by its own `<label>`. Moving with the arrow keys chooses as it goes, as the WAI-ARIA pattern says; <kbd>Space</kbd> chooses the radio in focus, and <kbd>Enter</kbd> does nothing.
