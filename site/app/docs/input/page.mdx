## When to use

Use an Input for one line of free text: a name, an email, a search. It renders a real `<input>`, so `type`, `name`, `autoComplete`, `pattern` and every other attribute reach it as they are, and `onValueChange` hands you the string without reading the event.

## Similar

- [Textarea](/docs/textarea/) takes several lines and grows with them.
- [NumberInput](/docs/number-input/) is for numbers: it refuses letters, steps with the arrows and formats by locale.
- [PasswordInput](/docs/password-input/) adds a show/hide button and a Caps Lock hint.
- [Combobox](/docs/combobox/) is a text field whose value must come from a list.

## Validate when the field is left

`isInvalid` and `errorMessage` are yours to set, so you choose when to check. Here the address is checked once focus has left the field, not while it is being typed.

## Checked by the browser

Inside a [Form](/docs/form/), the browser's own checks (`isRequired`, `type="email"`, `pattern`) show their message under the field instead of in a tooltip, and a blocked submit focuses the first field to fix. Press Invite with the email empty.

## Accessibility

The label is a `<label for>` the input, and the description or the error is its `aria-describedby`, so a screen reader reads it with the field. `isInvalid` sets `aria-invalid`. `isRequired` sets the native `required` attribute; the asterisk after the label is drawn in CSS. The clear button is a real button named "Clear", reachable with <kbd>Tab</kbd>, and it hands focus back to the field.

## Styling

`className` goes to the outer wrapper, which holds the label, the box and the text under it. `classNames` reaches the parts inside: `base`, `label`, `inputWrapper` (the box), `input`, `clearButton`, `description` and `errorMessage`.
