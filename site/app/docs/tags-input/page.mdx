## When to use

Use a TagsInput when the values are open-ended and short: topics, labels, reviewers, file patterns. People type them, paste a list, or let a phone keyboard insert them, and each one becomes a tag they can see and remove. Leftover text becomes a tag when the field loses focus, unless `addOnBlur` is `false`.

## Similar

- [Combobox](/docs/combobox/) with `selectionMode="multiple"` also shows its values as tags, but only takes them from its list. Use it when the choices are known.
- [Input](/docs/input/) holds one free value as a string.

## Rules and limits

`validate` refuses a tag by returning `false`, `maxTags` stops new ones once the field is full, and a tag that is already there in any letter case is refused unless `allowDuplicates` is set. A refused tag keeps its text in the field and shows the reason in place of the description until the text changes. `formatAnnouncement` words each reason. Try “Bug”, then “help wanted”, then add labels until a fourth is refused.

## Your own separators

`separators` lists the keys that add a tag; single characters also split text that is pasted or inserted without key events, as Android keyboards and autofill do. Line breaks in pasted text always split. Here a space adds a path too, so `site/** package.json` pasted at once becomes two tags.

## In a form

With a `name`, every tag is submitted as its own value, so `FormData.getAll()` returns the list. <kbd>Enter</kbd> with text in the field adds a tag; <kbd>Enter</kbd> in an empty field submits the form. `isRequired` counts the tags, not the text: with one tag in place the field is filled.

## Accessibility

The tags add no tab stops: <kbd>Tab</kbd> leaves the field rather than stepping through the remove buttons. With `isClearable`, the clear button is the next stop. From the empty field, <kbd>←</kbd> moves onto the last tag's remove button, the arrow keys walk the tags, <kbd>Backspace</kbd> or <kbd>Delete</kbd> removes the one in focus and focus moves to a neighbour, and <kbd>→</kbd> past the last tag or <kbd>Escape</kbd> returns to the field. A mouse click on a remove button puts focus back in the field.

Screen readers hear each change through a polite live region: "Added react", "Removed react", and every refusal, which is also linked to the field with `aria-describedby`. Remove buttons are named "Remove react"; translate them with `removeLabel` and the messages with `formatAnnouncement`.

## Styling

`classNames` reaches the inner parts: `base`, `label`, `inputWrapper`, `input`, `tag`, `clearButton`, `description` and `errorMessage`.
