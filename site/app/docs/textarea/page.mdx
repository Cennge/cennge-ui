## When to use

Use a Textarea for text that runs to more than a line: release notes, a comment, a description. It starts at `minRows` lines and grows with the text up to `maxRows`, so a short note takes little room and a long one does not push the page down without end.

## Similar

- [Input](/docs/input/) is one line, with a clear button and room for icons; a Textarea has neither.
- [TagsInput](/docs/tags-input/) turns typed words into separate tags instead of keeping one block of text.

## Rows to grow between

`minRows` sets the height of the empty field and `maxRows` the most it grows; past that the text scrolls inside the field. Both count lines of text.

## Send with a shortcut

Every other prop goes to the `<textarea>`, `onKeyDown` included. Here <kbd>Ctrl</kbd>+<kbd>Enter</kbd> or <kbd>⌘</kbd>+<kbd>Enter</kbd> posts the comment, while <kbd>Enter</kbd> alone still starts a new line.

## Accessibility

The label is a `<label for>` the textarea, and the description or the error is its `aria-describedby`. `isInvalid` sets `aria-invalid` and `isRequired` the native `required` attribute, so inside a [Form](/docs/form/) a named, required field that is empty shows the browser's message under it.

## Styling

It shares the Input's box: the same `variant`, `color`, `size` and `radius`. `className` goes to the outer wrapper; `classNames` reaches `base`, `label`, `inputWrapper`, `input`, `description` and `errorMessage`.
