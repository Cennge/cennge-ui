## When to use

A Checkbox is a choice that takes effect when the form around it is sent: agree to the terms, publish with provenance, include these labels. Several boxes in a list are independent of each other, and one more box above them can stand for the whole list.

## Similar

- [Switch](/docs/switch/) turns a setting on or off the moment it flips, with no form to submit.
- [Radio](/docs/radio/) is for one choice out of several; checkboxes allow any number.
- [Table](/docs/table/) selects rows with this Checkbox; `useTableSelection` tells the header box when all or some rows are checked.

## With a description

`description` sits under the label in smaller, muted text and is linked to the box with `aria-describedby`, so it is read after the label.

## Some, all or none

A parent box is checked when all its children are, mixed when some are, and empty when none are. Pass `isIndeterminate` for the mixed case; a click on a mixed box reports `true`, so the parent checks everything first.

</Example>

## Required, in a form

Inside a [Form](/docs/form/), `isRequired` stops a submit while the box is empty. The box turns red, the browser's message shows under the label, and focus moves to the box; checking it clears the error. A checked box submits `"on"` under its `name`, or your own `value`.

## Accessibility

The label is a real `<label>` for the box, so a click on the text toggles it and screen readers name the box by it. Without visible text, pass `aria-label`. <kbd>Space</kbd> toggles; <kbd>Enter</kbd> does nothing, as the WAI-ARIA checkbox pattern says. While `isInvalid`, the box carries `aria-invalid` and the error replaces the description.
