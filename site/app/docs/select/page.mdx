## When to use

A Select holds one value from a list you know in advance and that fits on a screen: a region, a license, a sort order. Nothing is typed, so a phone opens the list without covering it with a keyboard, and `isClearable` gives people a way back to "nothing chosen".

## Similar

- [Combobox](/docs/combobox/) filters as you type and can hold several values; use it when the list is long enough to search.
- [Radio](/docs/radio/) shows every choice at once. For a few options that people should compare, it saves a click.
- [Dropdown](/docs/dropdown/) runs actions from a menu; a Select keeps a value.

## Pick one, or none

The value is the chosen item's `value`, or `null` when nothing is chosen: never an empty string. `isClearable` adds a button that sets it back to `null`.

## Groups and descriptions

`SelectGroup` gives a run of options a heading, `SelectSeparator` draws a line between groups, and an item's `description` sits under its name. Disabled options stay in the list but cannot be chosen, and the arrow keys pass over them.

## In a form

With a `name`, the value goes into the form's data. Inside a [Form](/docs/form/), `isRequired` stops an empty submit: the browser's message shows under the field and the field gets focus.

## Accessibility

The field is a `combobox` named by its label; the description, or the error in its place, is linked with `aria-describedby`. While the list is open, focus stays in it: <kbd>Tab</kbd> does nothing, and <kbd>Escape</kbd> closes the list and puts focus back on the field. The clear button is a separate button named "Clear", next in the tab order after the field.

## Styling

`classNames` reaches the inner parts: `base`, `label`, `trigger`, `value`, `popover`, `clearButton`, `description` and `errorMessage`. Options take `className` on each `SelectItem`.
